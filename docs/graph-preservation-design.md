# 그래프와 원본 대조를 통한 문서 누락 방지

2026-09-15

## 문제와 계약

기존 파서는 호출을 180자 문자열, 최대 10,000개로 보관한다. 소스 이해는 최대 12개 관찰을 반복해서 종합하고, 다음 단계에는 선택된 관찰의 근거만 전달한다. 목적별 선택과 검색에도 표본 상한이 있다. 읽기 완료는 문서에 중요한 동작을 설명했다는 증거가 아니다.

개선의 계약은 **저장할 때 버리지 않고, 요청할 때 필요한 부분을 선택하고, 선택에서 빠진 원본도 최종 검토한다**이다. 임의 프로그램의 의미를 완전히 증명하지는 못한다. 동적 호출, 파싱 오류, 모델 검토 실패는 미확인 상태로 남긴다.

## 구조

1. Tree-sitter에서 모듈·클래스·타입·함수·메서드 노드와 소유 관계, 호출·의존·분기·반환·오류·대기·변경 위치를 추출한다. 경로 및 바이트 범위로 안정적인 ID를 만들고 원본 범위를 보존한다. 문자열 표본으로 그래프를 대체하지 않는다.
2. 그래프는 파일별 체크포인트에 저장한다. 이전 실행은 저장된 스냅샷으로 그래프를 복원한다. 현재 작업 파일을 다시 읽어 과거 실행의 근거를 바꾸지 않는다.
3. 검색은 명시한 심볼 및 직접 이웃의 원본을 우선한다. 이름 일치는 검색 후보이며 런타임 호출의 증명이 아니다. 예산에 들지 않는 근거를 잘라 넣지 않고 보류 수를 기록한다.
4. 요청에 싣는 그래프는 저장 레코드를 그대로 넣지 않고 읽기용으로 투영한다. 저장 전용 필드(심볼 ID, 바이트 오프셋)는 빼고, 대상이 없는 분기·반환·오류·대입·대기 위치는 심볼별 건수로 접는다. 한 줄에 하나씩 넣으면 예산 전부를 "여기에 분기가 있다"는 말에 쓰게 되고, 건수는 해당 원문이 이미 요청에 들어 있으므로 손실이 아니다.
5. 예산은 파일별로 한 건씩 돌아가며 배분한다. 경로 순으로 앞선 파일이 예산을 모두 소진해 나머지 파일이 구조 정보 없이 남는 일이 없어야 한다. 배분 순서는 선언 → 심볼별 분기·오류 건수 → 모듈 의존(import/inherits) → 개별 호출 위치다. 앞의 세 단계가 묶음의 골격이며, 가장 수가 많고 원문에서 다시 읽기 쉬운 개별 호출 위치가 마지막에 배분된다.
6. 싣지 못한 레코드는 총합이 아니라 파일별 건수로 알린다. 색인에 없거나 문법 지원이 없어 그래프 자체가 비어 있는 파일도 사유와 함께 알린다. 모델은 이를 미해결로 표시해야 하며, 해당 구조가 존재하지 않는다는 근거로 삼지 않는다.
7. 최초 읽기의 원본 근거를 모두 보존한다. 계층 요약은 탐색용 개요다. 요약에서 제거된 상세 관찰은 leaf 체크포인트에서 다시 조회한다. 계층 종합도 하위가 읽은 파일들의 구조 투영을 함께 받는다. 종합은 원문이 아니라 하위 요약을 읽으므로, 투영이 없으면 그래프에 분명히 있는 모듈 간 호출조차 미확인으로 버려야 한다. 투영의 연결은 구문 후보이므로 링크를 지목해 따라가되 실행을 단정하지 않는다.

8. 리프와 종합은 서로 다른 투영을 받는다. 리프는 원문을 함께 받으므로 선언과 심볼별 위치 건수가 먼저이고 호출은 원문에서 읽는다. 종합은 하위 요약을 읽으므로 각 심볼이 무엇을 하는지는 이미 요청 안에 있고, 없는 것은 파일 사이의 연결뿐이다. 따라서 종합에는 선언·심볼별 건수·같은 파일 안의 호출을 전부 빼고 예산 전부를 파일 간 호출에 쓴다. 같은 순서를 두 곳에 쓰면 종합에서 필요한 것이 가장 먼저 잘린다.

9. 파일 간 호출은 호출 지점마다가 아니라 심볼 쌍으로 접고 건수를 함께 보낸다. 같은 쌍이 여러 줄에서 호출되는 것이 보통이므로, 접지 않으면 표가 예산에 들어가지 않는다. 대상 이름을 한 파일만 선언하면 `경로::심볼`로 해석해 보내고, 여러 파일이 선언하면 해석하지 않은 채 후보 경로를 함께 보낸다. 해석된 링크는 이름만 있는 후보보다 훨씬 강한 주장이므로 모호한 것을 해석된 것처럼 보내지 않는다.

10. 호출 대상의 이름 해석은 run 전체에서 한 번만 수행하고 각 종합 노드는 자기 경로 집합으로 거른다. 이름 해석에는 프로젝트 전역 심볼 목록이 필요한데 이미 메모이즈된 전역 색인이 심볼과 호출 간선을 모두 가지고 있으므로 추가 조회가 없다. 노드마다 경로 수만큼 체크포인트를 다시 읽으면 파일 수에 선형인 작업이 노드 수만큼 반복된다.

11. 예산은 레코드가 아니라 힌트 전체를 묶는다. 안내문, 못 실은 것의 보고, 파일 목록도 요청이 나르는 바이트다. 레코드만 배분하면 파일이 많은 요청이 예산의 절반을 "못 실은 링크 목록"에 쓰고 허용치를 넘긴다. 못 실은 파일을 하나씩 나열하지 않고 총량과 손실이 큰 몇 개만 이름을 밝히며, 나머지 메타데이터를 먼저 재고 남는 자리에 링크를 담는다.

12. 경로는 공통 루트를 한 번만 말하고 그 뒤만 보낸다. 절대 경로는 레코드마다 루트를 두 번 반복하고(자기 경로와 지목한 대상), 모호한 레코드는 후보마다 또 반복한다. 루트를 빼면 레코드가 대략 절반이 되고, 같은 예산에 링크가 두 배 들어간다.

13. 보내지 못한 것은 종류별로 센다. 같은 파일 호출, 요청 범위 밖으로 나가는 호출, 어느 파일도 선언하지 않는 이름을 각각 세어 함께 보낸다. 그래프가 본 적 없는 파일과 그래프에는 있으나 링크가 없는 파일도 구분해 이름을 밝힌다. 종합이 "이 모듈은 아무와도 대화하지 않는다"로 읽는 것과 "여기서는 확인할 수 없다"로 읽는 것은 다르다.
8. 문서 생성 후 원본을 전수 재대조하는 절차는 두지 않는다. 실측에서 판정의 92%가 목적 범위 밖으로 돌아왔고, 한 프로젝트를 도는 데 몇 시간이 들었다. 그 비용으로 얻는 것이 "설명할 필요가 없는 것을 설명하지 않았다"는 확인이라면 값이 맞지 않는다. 누락은 대신 앞단에서 막는다 — 모든 청크를 읽고, 읽기 실패는 미해결로 남기며, 목차 검토가 빠진 주제를 잡고, 섹션 검토가 인용과 근거를 대조한다.
9. 그 대가로 포기하는 것을 분명히 한다. 원본을 다시 대조하지 않으므로 목적에 필요한 내용이 본문에서 빠졌는지를 원문 단위로 판정하지는 않는다. 대신 두 가지를 비용 없이 막는다. 첫째, 목차가 읽기 트리의 모든 브랜치를 절에 배정하거나 이유와 함께 제외해야 하며, 둘 다 아닌 브랜치는 코드로 계산해 목차 검토에 넘긴다. 둘째, 브랜치를 맡은 절은 검색 결과와 무관하게 그 브랜치의 리프 관찰 전체를 받는다. 발행물의 분석 범위 문구는 여전히 이 한계를 명시한다 — 모든 주장은 근거를 인용하고 각 섹션은 인용한 근거와 대조되지만, 요청에 실리지 않은 소스와는 대조되지 않는다.

## 컨텍스트와 재개

원본·문서 분할은 UTF-8 경계를 지키며 모든 바이트를 포함한다. 그래프 ID와 원본 ID, 실제 문서 및 모델 설정으로 검토 캐시를 구분한다. 본문 수정 이후 오래된 설명 확인을 재사용하지 않는다. 기존 토큰·시간·비용·취소 정책을 그대로 적용한다. 저장 그래프 전체를 매번 모델 컨텍스트에 넣지 않는다.

## 검증

8개 언어의 클래스/함수 구조, 같은 이름의 구분, 중첩 소유권, 긴 소스의 관계 보존, 이웃 선택, 요청 투영의 심볼별 위치 접기와 저장 전용 필드 제외, 파일별 예산 배분과 파일별 누락 명시, 파일 간 호출의 심볼 쌍 접기와 건수 보존, 힌트 전체의 예산 준수와 공통 루트 분리, 한 파일만 선언하는 이름의 해석과 여러 파일이 선언하는 이름의 미해석 유지, 같은 파일 호출·범위 밖 호출·미선언 이름의 구분 집계, 그래프 미확인 파일과 링크 없는 파일의 구분, UTF-8 분할, 완전한 원장 응답/정확한 문서 인용 검증, 오래된 캐시와 재개, 누락의 수정 루프 전달을 회귀 검증한다. 실제 모델의 의미 정확도와 추가 호출 비용은 별도 실측 대상으로 구분한다.

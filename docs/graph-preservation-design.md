# 그래프와 원본 대조를 통한 문서 누락 방지

2026-09-15

## 문제와 계약

기존 파서는 호출을 180자 문자열, 최대 10,000개로 보관한다. 소스 이해는 최대 12개 관찰을 반복해서 종합하고, 다음 단계에는 선택된 관찰의 근거만 전달한다. 목적별 선택과 검색에도 표본 상한이 있다. 읽기 완료는 문서에 중요한 동작을 설명했다는 증거가 아니다.

개선의 계약은 **저장할 때 버리지 않고, 요청할 때 필요한 부분을 선택하고, 선택에서 빠진 원본도 최종 검토한다**이다. 임의 프로그램의 의미를 완전히 증명하지는 못한다. 동적 호출, 파싱 오류, 모델 검토 실패는 미확인 상태로 남긴다.

## 구조

1. Tree-sitter에서 모듈·클래스·타입·함수·메서드 노드와 소유 관계, 호출·의존·분기·반환·오류·대기·변경 위치를 추출한다. 경로 및 바이트 범위로 안정적인 ID를 만들고 원본 범위를 보존한다. 문자열 표본으로 그래프를 대체하지 않는다.
2. 그래프는 파일별 체크포인트에 저장한다. 이전 실행은 저장된 스냅샷으로 그래프를 복원한다. 현재 작업 파일을 다시 읽어 과거 실행의 근거를 바꾸지 않는다.
3. 검색은 명시한 심볼 및 직접 이웃의 원본을 우선한다. 이름 일치는 검색 후보이며 런타임 호출의 증명이 아니다. 예산에 들지 않는 근거를 잘라 넣지 않고 보류 수를 기록한다.
4. 요청에 싣는 그래프는 저장 레코드를 그대로 넣지 않고 읽기용으로 투영한다. 저장 전용 필드(심볼 ID, 바이트 오프셋)는 빼고, 대상이 없는 분기·반환·오류·대입·대기 위치는 심볼별 건수로 접는다. 한 줄에 하나씩 넣으면 예산 전부를 "여기에 분기가 있다"는 말에 쓰게 되고, 건수는 해당 원문이 이미 요청에 들어 있으므로 손실이 아니다.
5. 예산은 파일별로 한 건씩 돌아가며 배분한다. 경로 순으로 앞선 파일이 예산을 모두 소진해 나머지 파일이 구조 정보 없이 남는 일이 없어야 한다. 배분 순서는 선언 → 심볼별 분기·오류 건수 → 모듈 의존(import/inherits) → 개별 호출 위치다. 앞의 세 단계가 묶음의 골격이며, 가장 수가 많고 원문에서 다시 읽기 쉬운 개별 호출 위치가 마지막에 배분된다.
6. 싣지 못한 레코드는 총합이 아니라 파일별 건수로 알린다. 색인에 없거나 문법 지원이 없어 그래프 자체가 비어 있는 파일도 사유와 함께 알린다. 모델은 이를 미해결로 표시해야 하며, 해당 구조가 존재하지 않는다는 근거로 삼지 않는다.
7. 최초 읽기의 원본 근거를 모두 보존한다. 계층 요약은 탐색용 개요다. 요약에서 제거된 상세 관찰은 leaf 체크포인트에서 다시 조회한다. 계층 종합도 하위가 읽은 파일들의 구조 투영을 함께 받는다. 종합은 원문이 아니라 하위 요약을 읽으므로, 투영이 없으면 그래프에 분명히 있는 모듈 간 호출조차 미확인으로 버려야 한다. 투영의 연결은 구문 후보이므로 링크를 지목해 따라가되 실행을 단정하지 않는다.
8. 최종 검토는 요약을 거치지 않고 색인 소스를 순회한다. 순회 순서는 문서가 인용한 파일, 분석이 관련 있다고 판단한 파일, 나머지 순이다. 앞의 둘이 독자가 잘못된 설명을 읽거나 검색이 놓친 파일이 드러나는 자리다. 실행 예산이 전부를 감당하면 셋 다 순회하고, 그렇지 못하면 남은 예산으로 문서를 마칠 수 있는 지점에서 의도적으로 멈춘다. 감사한 파일 수와 감사하지 못한 파일 수는 원장·경고·발행물에 명시한다. 감사하지 못한 것을 감사한 것처럼 두지 않는다. 원본과 그래프를 제한된 묶음으로 나누고 완전한 문서의 모든 구간과 대조한다. 각 묶음은 설명 확인, 목적 범위 밖(이유 필수), 누락 상태를 갖는다. 설명 확인에는 실제 문서 인용문이 필요하다. 일부 발췌에 없다는 이유만으로 누락 판정하지 않는다.
9. 대조 의무는 구현 파일의 선언(함수·메서드·클래스·타입·인터페이스·모듈)으로 한정한다. 독자가 찾아보는 단위가 선언이기 때문이다. 실제 실행 측정에서 그 밖의 의무는 92%가 목적 범위 밖으로 판정됐고, 그 예산은 정말 누락된 설명을 찾는 데 쓰였어야 할 몫이다. 잠금 파일·페이지 템플릿처럼 선언이 없는 파일은 감사 대상에서 제외하고 그 수를 발행물에 명시한다. 포기하는 것은 개별 분기·종료 지점과 선언 밖 최상위 코드의 개별 확인이며, 그래프에는 그대로 기록된다. 여러 구절의 의무를 한 요청에 함께 싣는다 — 한 구절에 의무가 하나뿐인데 문서 페이지와 지시문을 통째로 실어 보내는 것이 비용의 대부분이었다. 참고로 통합 이전 형태는 연결마다 하나, 심볼의 분기·반환·오류·대입·대기 부류마다 하나였다. `if` 하나하나와 같은 대상을 향한 반복 호출마다 의무를 따로 두면 독자가 다르게 답할 수 없는 질문을 수천 개 만든다. 사이트 수와 행 범위가 해당 심볼의 조건·오류·취소 동작을 설명할 의무를 그대로 담는다. 한 요청에 싣는 의무 수는 남은 공간이 허용하는 만큼이며, 이미 문서 페이지와 원문 구절을 싣고 가는 요청에 의무 몇 개만 넣지 않는다.
10. 설명 확인의 인용문은 해당 페이지의 산문과 공백을 평탄화해 대조한다. 코드 리터럴은 산문에서 제외한다. 담당 섹션 번호는 설명 확인에서는 대조 중인 페이지로 확정하며 모델에게 되풀이시키지 않는다.
11. 판정 하나가 잘못되어도 묶음 전체를 버리지 않는다. 받아들일 수 있는 판정은 보존하고 확정하지 못한 의무만 다시 묻는다. 미확정 의무가 지목한 담당 섹션의 페이지를 다음 순서로 확인한다. 지목은 "어디에 있다"가 아니라 "어디가 맡아야 한다"이므로 틀려도 순서만 바뀌며, 누락 판정 전에 모든 페이지를 확인하는 계약은 그대로다. 끝내 확정하지 못한 의무는 실행을 중단시키지 않고 미확정으로 원장과 경고에 남긴다. 미확정은 문서가 무언가를 빠뜨렸다는 판정이 아니라 대조를 마치지 못했다는 사실이다.
12. 누락은 기존 본문 수정 루프로 전달한다. 잘못된 검토 응답이나 예산 소진은 검토 완료로 취급하지 않는다. 모든 대조를 마치고 핵심 누락을 해결해야 일반 완료가 가능하다. 검토 한도 뒤 남은 누락은 경고 결과와 누락 원장으로 드러난다.

## 컨텍스트와 재개

원본·문서 분할은 UTF-8 경계를 지키며 모든 바이트를 포함한다. 그래프 ID와 원본 ID, 실제 문서 및 모델 설정으로 검토 캐시를 구분한다. 본문 수정 이후 오래된 설명 확인을 재사용하지 않는다. 기존 토큰·시간·비용·취소 정책을 그대로 적용한다. 저장 그래프 전체를 매번 모델 컨텍스트에 넣지 않는다.

## 검증

8개 언어의 클래스/함수 구조, 같은 이름의 구분, 중첩 소유권, 긴 소스의 관계 보존, 이웃 선택, 요청 투영의 심볼별 위치 접기와 저장 전용 필드 제외, 파일별 예산 배분과 파일별 누락 명시, UTF-8 분할, 완전한 원장 응답/정확한 문서 인용 검증, 오래된 캐시와 재개, 누락의 수정 루프 전달을 회귀 검증한다. 실제 모델의 의미 정확도와 추가 호출 비용은 별도 실측 대상으로 구분한다.

검증일: 2026-09-14. 구현 자동 검사는 통과했다. 실제 모델 실행은 사용자 지정 **2회 검토**로 종료되어 문서를 저장했으며, 문서 품질은 **검토 사항 있음**이다.

## 구현 검증

- Rust 단위 검사: 64 통과, 별도 DB 환경이 필요한 9개는 제외.
- Clippy 경고 없음, TypeScript/Vite 빌드 통과.

- 512개 파일과 기존 `max_files=1` 설정으로 파일 페이지를 끝까지 순회하고, 실제 분석 요청에 512개 파일 모두 포함됨을 검사했다.
- 목차 보정 성공, 2회 보정 후 미해결 시 대기, 미리보기 승인, 편집 요청 중복 방지, 오래된 버전 거절을 확인했다.
- 본문 작성 후 재계획 전후의 검토 횟수가 공통 `max_iterations=3`을 넘지 않음을 확인했다.
- UTF-8 및 긴 줄을 분할해도 원문이 유실되지 않고, 선행 섹션 변경이 종속 초안 캐시를 무효화함을 확인했다.

실제 모델이 최종 읽기에서도 추가 탐색 질문을 반환해 초기 실행이 중단되었다. 최종 단계의 질문은 실행하지 않고 미확인 연결로 보존하도록 보완했다. 빈 질문은 제거하고, 최종 단계에서는 최대 8개까지 보존한다. 실제 추가 탐색 단계의 3개 제한은 유지한다. 수정 후 같은 실행의 성공한 읽기 체크포인트를 재사용했다. 이 수정은 실행 시작 후 이루어졌으므로 분석 대상 소스 스냅샷과 최종 구현은 일부 다르다.

후속 실제 검증에서는 테스트·문서 근거를 runtime으로 분류한 응답이 거절되었다. 재시도에 해당 관찰과 근거 파일의 분류를 명시하도록 개선했다. 시작 스크립트(`sh`, `bat` 등)는 실제 구현 근거로 인정하도록 분류를 보완하고, 테스트 경로의 스크립트는 계속 context로 처리하는 회귀 검사를 추가했다.

초기 전체 요약을 직접 확인한 결과, 원문을 상위 요청에 다시 넣을 때의 크기 제한 때문에 이미 확인한 백엔드 주요 흐름이 탈락했다. 실제 실행을 일시 중단하고, 종합·목적별 읽기·목차 계획에서 검증된 하위 관찰과 원문 근거 ID를 유지하도록 수정했다. 새 연결은 별도 근거를 요구하며, 하위 관찰의 인용은 보존된 원문에 대조한다. 목차 검토의 원문 입력도 크기를 제한했다. 34개 읽기 묶음은 재사용하고 종합부터 재검증했다. 초기 요약과 체크포인트는 로컬 검증 기록으로 보존했다.

마지막 종합은 일부 원문 발췌를 재선택하지 않고, 검증된 하위 관찰과 근거 앵커 전체를 입력으로 사용하도록 추가 보완했다. 최종 요약에서 부팅/API/실행·복구/LLM 예산/계획·목차 편집/본문 검토·수리/검색·게시/UI 상태·뷰어가 함께 유지되는 것을 직접 확인했다. 의존성·테스트 상세가 제품 동작을 밀어내지 않도록 종합 지시를 명확히 했다.

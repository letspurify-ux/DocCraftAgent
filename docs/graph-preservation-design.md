# 그래프와 원본 대조를 통한 문서 누락 방지

2026-09-15

## 문제와 계약

기존 파서는 호출을 180자 문자열, 최대 10,000개로 보관한다. 소스 이해는 최대 12개 관찰을 반복해서 종합하고, 다음 단계에는 선택된 관찰의 근거만 전달한다. 목적별 선택과 검색에도 표본 상한이 있다. 읽기 완료는 문서에 중요한 동작을 설명했다는 증거가 아니다.

개선의 계약은 **저장할 때 버리지 않고, 요청할 때 필요한 부분을 선택하고, 선택에서 빠진 원본도 최종 검토한다**이다. 임의 프로그램의 의미를 완전히 증명하지는 못한다. 동적 호출, 파싱 오류, 모델 검토 실패는 미확인 상태로 남긴다.

## 구조

1. Tree-sitter에서 모듈·클래스·타입·함수·메서드 노드와 소유 관계, 호출·의존·분기·반환·오류·대기·변경 위치를 추출한다. 경로 및 바이트 범위로 안정적인 ID를 만들고 원본 범위를 보존한다. 문자열 표본으로 그래프를 대체하지 않는다.
2. 그래프는 파일별 체크포인트에 저장한다. 이전 실행은 저장된 스냅샷으로 그래프를 복원한다. 현재 작업 파일을 다시 읽어 과거 실행의 근거를 바꾸지 않는다.
3. 검색은 명시한 심볼 및 직접 이웃의 원본을 우선한다. 이름 일치는 검색 후보이며 런타임 호출의 증명이 아니다. 예산에 들지 않는 근거를 잘라 넣지 않고 보류 수를 기록한다.
4. 최초 읽기의 원본 근거를 모두 보존한다. 계층 요약은 탐색용 개요다. 요약에서 제거된 상세 관찰은 leaf 체크포인트에서 다시 조회한다.
5. 최종 검토는 요약을 거치지 않고 모든 색인 소스를 순회한다. 원본과 그래프를 제한된 묶음으로 나누고 완전한 문서의 모든 구간과 대조한다. 각 묶음은 설명 확인, 목적 범위 밖(이유 필수), 누락 상태를 갖는다. 설명 확인에는 실제 문서 인용문이 필요하다. 일부 발췌에 없다는 이유만으로 누락 판정하지 않는다.
6. 누락은 기존 본문 수정 루프로 전달한다. 잘못된 검토 응답이나 예산 소진은 검토 완료로 취급하지 않는다. 모든 대조를 마치고 핵심 누락을 해결해야 일반 완료가 가능하다. 검토 한도 뒤 남은 누락은 경고 결과와 누락 원장으로 드러난다.

## 컨텍스트와 재개

원본·문서 분할은 UTF-8 경계를 지키며 모든 바이트를 포함한다. 그래프 ID와 원본 ID, 실제 문서 및 모델 설정으로 검토 캐시를 구분한다. 본문 수정 이후 오래된 설명 확인을 재사용하지 않는다. 기존 토큰·시간·비용·취소 정책을 그대로 적용한다. 저장 그래프 전체를 매번 모델 컨텍스트에 넣지 않는다.

## 검증

8개 언어의 클래스/함수 구조, 같은 이름의 구분, 중첩 소유권, 긴 소스의 관계 보존, 이웃 선택, UTF-8 분할, 완전한 원장 응답/정확한 문서 인용 검증, 오래된 캐시와 재개, 누락의 수정 루프 전달을 회귀 검증한다. 실제 모델의 의미 정확도와 추가 호출 비용은 별도 실측 대상으로 구분한다.

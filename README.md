# DocCraft Agent

로컬 소스 코드를 목적별 Markdown 문서로 만드는 Rust + React 애플리케이션입니다. 여러 문서화 작업, 근거 인용, Mermaid 흐름도, 자동 검토·개선, 취소·복구, 문서 버전 비교를 지원합니다.

## 실행

필요한 도구는 Rust 1.93 이상, Node.js 22 이상, 로컬 MariaDB입니다. MariaDB를 새로 설치하거나 Docker로 실행하지 않습니다.

macOS/Linux에서 백엔드와 프론트엔드를 함께 실행합니다.

```sh
./start_all.sh
```

Windows에서는 프로젝트 폴더에서 다음 스크립트를 사용합니다(Node.js·npm, Rust·Cargo가 PATH에 있어야 합니다).

```bat
start_all.bat
```

중지하려면 다른 CMD 창에서 `stop_all.bat`를 실행합니다. PowerShell에서는 `./start_all.bat`, `./stop_all.bat`를 사용합니다. 경로에 공백이 있어도 실행할 수 있습니다. Windows는 PowerShell/CIM으로 프로세스 생성 시각과 명령을 확인하고, 시작 관리자가 중지 요청을 받아 자식 트리를 `taskkill /T /F`로 종료합니다. Windows 종료는 강제 종료이므로 진행 중인 분석은 마지막 저장 체크포인트부터 복구됩니다. macOS/Linux는 SIGINT로 정상 종료를 먼저 요청합니다.

프론트엔드 **http://127.0.0.1:6001**, 백엔드 **http://127.0.0.1:8765**가 실행됩니다. 시작 스크립트는 터미널에서 계속 실행되며, `Ctrl+C` 또는 다른 터미널에서 다음 명령으로 둘 다 중지합니다.

```sh
./stop_all.sh
```

`start_all`이 실행한 프로세스만 중지합니다. 이미 다른 서버가 포트를 사용 중이면 시작을 거절합니다. 실행 기록은 `.local/all-processes.json`에 저장합니다. 시작 시 Rust를 빌드하고, 프론트엔드 의존성이 없으면 `npm ci`를 실행합니다. 한 서버가 종료되면 나머지도 종료합니다. 종료는 최대 8초 기다린 뒤 남은 자식 프로세스 그룹을 강제 종료합니다.

포트가 다른 앱에 점유된 경우 그 앱을 임의로 종료하지 않습니다. 예를 들어 대체 포트로 실행하려면 `DOCCRAFT_PORT=8766 DOCCRAFT_FRONTEND_PORT=6002 ./start_all.sh`를 사용할 수 있습니다.

`DOCCRAFT_PORT`로 백엔드 포트, `DOCCRAFT_FRONTEND_PORT`로 프론트엔드 포트를 변경할 수 있으며 API 프록시도 같은 백엔드 포트로 연결됩니다. 기존 `node scripts/start.mjs`는 빌드된 UI를 Rust 서버 하나로 제공하는 실행 방식입니다.

두 서버를 별도 터미널에서 독립적으로 실행·중지할 수도 있습니다.

```sh
./start_backend.sh
./start_frontend.sh

./stop_backend.sh
./stop_frontend.sh
```

Windows에서는 각각 `start_backend.bat`, `start_frontend.bat`, `stop_backend.bat`, `stop_frontend.bat`를 사용합니다. 개별 시작 스크립트도 터미널에서 계속 실행됩니다. 각 중지 스크립트는 대응하는 개별 시작 스크립트가 실행한 서버만 중지하며, `start_all`이나 다른 명령으로 실행한 프로세스는 건드리지 않습니다. 포트 환경변수는 통합 실행과 동일합니다.

제공된 로컬 DB 계정은 이 환경의 `.local/settings.enc`에 암호화하여 설정합니다. 다른 환경에서는 화면의 **설정 → MariaDB**에서 계정을 입력하고 저장하세요. 최초 부트스트랩에만 `DOCCRAFT_DB_PASSWORD` 환경변수를 사용할 수도 있습니다.

1. **설정 → LLM 연결**에서 API 주소·모델·키를 입력하고 연결 테스트를 실행합니다.
2. **컨텍스트 · Reasoning**에서 모델의 실제 한도와 파라미터 방식을 설정합니다.
3. **경로 · 실행 정책**에서 존재하는 소스·출력 디렉터리를 허용 루트로 등록합니다.
4. **새 작업**에서 소스 경로, 대상 `.md` 경로, 원하는 문서 생성 방향을 입력합니다.
5. 실행하면 파일 분석, 작성, 검토·수정, 최종 저장까지 자동으로 진행합니다.

LLM 기본값은 추론 off, 최대 출력 16,384토큰입니다. 모델별 추론 파라미터 지원 여부는 연결 테스트로 확인하세요. 입력·출력·안전 여유를 합산해 최대 200k 컨텍스트를 검사하며, 출력 한도를 늘리면 사용할 수 있는 입력 공간은 줄어듭니다.

부분 문서는 실행 상세의 재개 기능으로 완료된 섹션을 재사용할 수 있습니다. **현재 LLM 설정 적용**을 선택하면 새 추론·출력 설정도 반영합니다. 기본적으로 기존 실행 한도를 유지합니다. 작업을 수정한 뒤 **현재 작업의 토큰 한도 적용**도 선택하면 새 토큰 한도를 사용합니다. 누적 사용량과 시간·비용 한도는 유지합니다. 성공 응답의 확인된 토큰 사용량은 예약량과 정산하고, 사용량을 알 수 없는 실패 요청은 보수적으로 유지합니다.

출력 디렉터리는 먼저 만들어야 합니다. 설정은 활성 실행이 없을 때 변경할 수 있습니다. 설정의 비밀번호 칸에 표시되는 `********`는 기존 값을 유지한다는 뜻입니다.

## 문서 구성 방식

목차를 정하기 전에 생성 방향과 관련된 실제 구현 본문을 읽어 진입점, 준비 조건, 주요 처리, 결과와 예외를 근거와 함께 정리합니다. 연결이 불분명하면 최대 3개 검색으로 한 차례 추가 확인하고, 남은 의문은 불확실성으로 유지합니다. 그 결과를 바탕으로 독자 목표, 전체 설명 흐름, 공통 용어와 절별 질문을 계획합니다. 각 절은 먼저 읽어야 할 절과 다음 절로 이어지는 결과를 가지며, 계획에 사용한 원본 코드 근거도 본문 작성에 전달합니다. 예를 들어 관리자 문서는 실제 구현에 맞춰 전체 동작 이해 → 준비 → 첫 실행 → 결과 확인 → 운영·문제 해결로 구성할 수 있습니다. 소스 파일명은 검색 단서로 사용하며, 파일 목록만으로 목차를 확정하지 않습니다.

작성과 수정에는 공통 계획 및 앞뒤 절의 제한된 발췌문을 전달합니다. 개별 절의 사실·인용 검토와 별도로 전체 문서의 중복, 용어, 전제 설명 순서와 연결성을 검토하며, 지적된 절을 수정한 후 다시 검토합니다. 전역 검토에는 크기가 제한된 발췌문을 사용하므로 모든 문장을 비교했다고 주장하지 않습니다. 모든 호출은 기존 컨텍스트·실행 예산과 취소 정책을 따릅니다.

인용 검증과 각주 변환은 코드 예시 밖의 인용에 적용합니다. 인라인 코드와 코드 블록에 표시된 `[E:id]` 같은 문법 예시는 원문으로 보존하며, 실제 근거 인용으로 세지 않습니다. 본문에서 제공되지 않은 근거를 인용하면 수정 대상으로 처리합니다.

본문 근거는 짧은 각주로 표시하고 원본 경로·행 범위·근거 ID는 참조 목록에 보존합니다. 미해결 경고는 상단에 요약하고 상세는 문서 끝과 라이브러리의 접을 수 있는 목록에서 확인합니다. 구현 사전 읽기는 일반적으로 LLM 요청 1~2회를 추가하며 기존 시간·토큰·비용 한도를 따릅니다. 이 구성 계획은 새 실행에 적용하며, 기존 목차 체크포인트와 생성 파일을 자동 변환하지 않습니다.

## 개발 및 검증

```sh
cargo run
npm --prefix frontend run dev
```

프론트엔드 개발 서버의 기본 주소는 http://127.0.0.1:6001 이며 API 요청은 Rust 서버(기본 8765번)로 전달됩니다. 6001번 포트가 사용 중이면 다른 포트로 자동 변경하지 않고 오류로 종료합니다.

```sh
cargo test --locked
node scripts/test-all.mjs # 통합 실행/중지 검사: start_all 미실행 상태에서 실행
node scripts/test-services.mjs # 개별 실행/중지 및 상호 독립성 검사
cargo clippy --all-targets -- -D warnings
npm --prefix frontend run build
npm --prefix frontend run generate:api
```

실제 로컬 MariaDB와 모의 OpenAI 서버를 사용하는 통합 테스트:

```sh
# DOCCRAFT_DB_PASSWORD를 현재 셸에서 설정한 뒤 실행
python3 scripts/smoke.py
```

요청 연결 종료와 DB deadlock 회귀 테스트는 별도 MariaDB 인스턴스에서 실행합니다. `DOCCRAFT_TEST_DB_PASSWORD`를 해당 인스턴스의 root 암호로 설정한 뒤 실행하세요. 테스트마다 `doccraft_agent_test_<UUID>` 스키마를 생성해 오류를 주입하며, 검사가 끝나면 해당 스키마를 삭제합니다.

```sh
DOCCRAFT_TEST_DB_PORT=3306 cargo test --locked -- --ignored --test-threads=1
```

`DOCCRAFT_UI_TEST=1`을 추가하면 Playwright 브라우저 테스트를 실행합니다. 먼저 `frontend`에서 `npx playwright install chromium`을 실행하세요. `DOCCRAFT_LARGE_TEST=1`은 10만·100만 줄의 구조 분석과 캐시 재실행을 추가합니다. 테스트는 `doccraft_agent_test`에만 애플리케이션 데이터를 기록합니다. 기존 테스트 결과는 보존 기간에 따라 정리됩니다.

## 구성

- `backend/src`: API, 실행 상태 머신, 소스 색인, 격리 파서, LLM 예산 검사, 파일 게시·복구.
- `backend/migrations`: 전용 MariaDB 스키마와 공유 근거 청크.
- `frontend/src`: React 화면, OpenAPI에서 생성한 타입.
- `scripts/smoke.py`: 장애를 주입하는 통합 테스트와 선택적 대형 소스 벤치마크.
- [설계와 운영](docs/architecture.md): 상태, 컨텍스트 계약, 복구, 저장소와 한계.

## 데이터와 운영

업무 DB는 `doccraft_agent`, 테스트 DB는 `doccraft_agent_test`만 허용합니다. 기존 다른 데이터베이스를 변경하지 않습니다. 로컬 `.local/`에는 암호화 설정, 암호화 키, 스냅샷과 복구 저널이 들어갑니다. **DB 백업과 `.local/` 백업을 함께 보관하세요.** 암호화 키가 없으면 저장된 실행 설정을 복호화할 수 없습니다.

앱은 loopback 주소에만 바인딩합니다. 기본 포트는 `8765`이며 `DOCCRAFT_PORT`로 변경할 수 있습니다. `DOCCRAFT_DATA_DIR`로 로컬 데이터 경로를 변경할 수 있습니다. 키·암호·원본 LLM 요청은 로그에 출력하지 않습니다. 소스 코드와 생성 문서는 로컬 DB 및 설정한 LLM 서버로 전달됩니다.

## 검증 범위

실제 LLM 품질 검증에는 사용자의 API 주소·모델·키가 필요합니다. 통합 테스트의 LLM은 오류 복구와 전체 흐름을 확인하는 모의 서버입니다. 벤치마크 시간은 실제 모델의 추론 시간을 의미하지 않습니다.

추정 토큰 모드는 서버의 토크나이저·숨겨진 템플릿 차이 때문에 초과 오류를 절대 배제하지 못합니다. 서버 토큰 계산 URL을 제공하면 계산 계약을 강화할 수 있습니다. 원격 서버 내부 추론은 HTTP 연결 종료 후에도 계속될 수 있습니다.

Windows·Linux·macOS용 CI 정의를 포함합니다. 현재 로컬에서 실행한 검증과 CI에서 아직 실행하지 않은 플랫폼 검증은 구분합니다.

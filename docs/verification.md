# 검증 결과

현재 로컬 macOS에서 다음 검증을 실행했다.

- Rust 단위·property 테스트 17개 통과: 토큰 경계, Unicode 청크 분할, 8개 언어 파싱, 근거 ID, 허용 경로, symlink 차단, 설정 암호화, 파일 교체.
- `cargo clippy --all-targets -- -D warnings` 및 Rust 포맷 검사 통과.
- TypeScript 검사와 Vite production build 통과.
- 실제 로컬 MariaDB `doccraft_agent_test`를 사용하는 통합 테스트 통과.

통합 테스트는 reasoning on/off 매핑, 명시적 HTTP proxy, 일반 생성, context 오류, 429 재시도, 잘못된 인용 수정, 검토 이슈에 따른 추가 iteration, 잘린 출력 재생성, 취소, 경로 차단, 캐시, 외부 파일 수정 충돌, 프로세스 재시작 및 DB 연결 장애 후 자동 복구를 포함한다. MariaDB 서비스 자체를 중단하지 않고 테스트 앱의 TCP 연결만 격리해서 차단했다.

최종 취소 테스트는 약 0.233초에 종료되었으며 출력 파일이 생성되지 않았다. [최종 통합 실행 기록](smoke-results.json)을 참고한다.

## 실제 실행 후 품질 개선

- 각 작성·검토 요청에 담당 섹션과 나머지 섹션 제목을 전달한다. 전체 목적을 모든 섹션에서 반복하지 않도록 지시하고, 중복 섹션 제목을 제거하며 하위 제목 계층을 보정한다.
- 인용·Mermaid 오류 수정은 기존 초안과 같은 근거를 유지한다. 출력 잘림은 목표 단어 수만 줄이고, 입력 컨텍스트 초과만 검색 근거 크기를 줄인다. 모든 요청은 기존 컨텍스트 사전 검사를 통과해야 한다.
- 검색어는 섹션 계획과 검토 이슈에서 구성한다. 후보는 파일당 최대 8개 청크로 제한하고, 서로 다른 구현 파일의 첫 근거를 문서·반복 청크보다 먼저 배치한다. 실제 동작 주장은 구현 근거를 요구하고 없으면 미확인으로 표시하도록 작성·검토 요청을 강화했다. 이는 의미 정확성의 절대 보장이 아니다.
- 신규 문서는 부분 생성/미해결 사항을 상단에 표시한다. 라이브러리는 기존 부분 산출물에도 경고를 표시한다. 기존 Markdown 산출물은 재작성하지 않았다.
- 검증: Rust 테스트 17개, Clippy, TypeScript/Vite 빌드, 로컬 MariaDB+모의 LLM 통합 테스트 및 Playwright 3개 통과. 통합 검사에서 인용·Mermaid 수정의 근거 유지, 출력 잘림의 분량 축소, 중복 제목 제거, 일일 한도 시 단일 거절 후 부분 저장을 확인했다.
- 실제 LLM을 사용하는 전체 재생성·반복 검토는 이번 개선에서 수행하지 않았다. 따라서 실제 문서 품질과 생성 시간의 개선 폭은 아직 측정되지 않았다.

## 실제 실행 후 품질 개선

- 각 작성·검토 요청에 담당 섹션과 나머지 섹션 제목을 전달한다. 전체 목적을 모든 섹션에서 반복하지 않도록 지시하고, 중복 섹션 제목을 제거하며 하위 제목 계층을 보정한다.
- 인용·Mermaid 오류 수정은 기존 초안과 같은 근거를 유지한다. 출력 잘림은 목표 단어 수만 줄이고, 입력 컨텍스트 초과만 검색 근거 크기를 줄인다. 모든 요청은 기존 컨텍스트 사전 검사를 통과해야 한다.
- 검색어는 섹션 계획과 검토 이슈에서 구성한다. 후보는 파일당 최대 8개 청크로 제한하고, 서로 다른 구현 파일의 첫 근거를 문서·반복 청크보다 먼저 배치한다. 실제 동작 주장은 구현 근거를 요구하고 없으면 미확인으로 표시하도록 작성·검토 요청을 강화했다. 이는 의미 정확성의 절대 보장이 아니다.
- 신규 문서는 부분 생성/미해결 사항을 상단에 표시한다. 라이브러리는 기존 부분 산출물에도 경고를 표시한다. 기존 Markdown 산출물은 재작성하지 않았다.
- 검증: Rust 테스트 17개, Clippy, TypeScript/Vite 빌드, 로컬 MariaDB+모의 LLM 통합 테스트 및 Playwright 3개 통과. 통합 검사에서 인용·Mermaid 수정의 근거 유지, 출력 잘림의 분량 축소, 중복 제목 제거, 일일 한도 시 단일 거절 후 부분 저장을 확인했다.
- 실제 LLM을 사용하는 전체 재생성·반복 검토는 이번 개선에서 수행하지 않았다. 따라서 실제 문서 품질과 생성 시간의 개선 폭은 아직 측정되지 않았다.

## 6001번 프론트엔드 작업 등록 오류

백엔드 Origin 허용 목록에 이전 Vite 포트 5173이 남아 POST가 빈 403으로 거절되고, 프론트엔드의 무조건적인 `response.json()`이 파싱 예외를 표시했다. 허용 포트를 `DOCCRAFT_FRONTEND_PORT`(기본 6001)와 `DOCCRAFT_PORT`에서 읽도록 수정하고 403도 JSON 오류를 반환한다. 프론트엔드는 빈 응답·HTML 오류 응답을 HTTP 상태별 오류로 처리하며 등록 요청을 자동 재전송하지 않는다.

검증: Rust 18개 및 Clippy 통과, API 응답 오류 테스트 통과, TypeScript/Vite 빌드 통과. 로컬 테스트 MariaDB의 등록 요청에 6001 Origin을 포함한 통합 테스트와 UI 4개 통과. 통합 실행 스크립트 테스트에서는 임의 설정한 프론트엔드 포트에서 프록시를 거친 POST가 Origin 검증을 통과하는 것도 확인했다. 실제 앱을 6001/8765로 재시작해 반영했다.

## 관리자 매뉴얼 테스트 중 복구·출력 설정 개선 (2026-09-13)

실제 실행 `4675e11c-4188-40d9-80f9-69c96114a638`에서 응답 본문 수신 중 연결 종료/타임아웃이 LLM 재시도를 우회하는 문제를 수정했다. HTTP 200에 포함된 제공자 오류도 정상 응답으로 집계하지 않고 제한된 재시도로 처리한다. 재시도 소진 시 완성된 섹션은 부분 문서로 보존한다.

추론 기본값은 off, 최대 출력은 16,384토큰으로 변경했다. 사용자 저장 설정에도 적용하고 실제 제공자 연결 테스트에서 추론 0토큰을 확인했다. 입력·출력·안전 여유의 최대 200k 검사와 작업의 총 200만 토큰 한도는 유지했다. 확인된 성공 응답 사용량만 예약량과 정산하며, 실패·사용량 불명 요청의 예약은 유지한다. 이전 버전의 확인된 초과 예약 정산은 체크포인트로 한 번만 수행한다.

부분 문서 재개 시 완료 섹션을 재사용하며, 선택적으로 현재 LLM 설정을 적용한다. 수정된 실행 스냅샷을 저장해 재시작 후에도 유지하고, 이전 부분 파일의 해시를 기준으로 정상 교체와 외부 수정 충돌을 구분한다. 화면에는 DB/API 갱신 실패를 명시해 오래된 실행 상태를 정상 상태로 오인하지 않도록 했다. 검토 진행에는 실제 담당 섹션을 표시하고, 검토 모델에 정확한 설명을 수정 이슈로 반환하지 않도록 명시했다.

실행/중지 스크립트 검사는 별도 임시 상태 디렉터리를 사용한다. macOS에서 시작, 사용자 지정 프록시, 중복 실행 방지, 종료, Ctrl+C 및 포트 해제를 확인했다. Windows 네이티브 실행은 이번 환경에서 검증하지 않았다.

검증: Rust 18개, Clippy, TypeScript/Vite 빌드, 로컬 MariaDB 통합 검사 및 Playwright 5개 통과. 추가 회귀 검사는 응답 본문 연결 종료, HTTP 200 오류, 부분 결과의 현재 설정 재개/교체, 고정 50,000토큰 예산에서 확인된 사용량 정산을 포함한다. 최종 취소는 약 0.240초에 완료됐다.

사용자 요청에 따라 등록 작업과 동일 실행의 총 토큰 한도를 10,000,000으로 변경했다. 재개 옵션 `current_token_limit`은 저장된 작업의 토큰 한도만 명시적으로 적용하며, 소스 스냅샷·완료 섹션·누적 사용량·시간 및 비용 한도는 유지한다. 실행 이벤트의 `max_tokens: 10000000`으로 실제 반영을 확인했다. 해당 옵션을 사용하는 재개와 최종 UI 5개 검사가 통과했다.

실제 보정 초안 3개를 당시 검색 근거와 대조해 같은 인용 2개가 반복해서 빠지는 것을 확인했다. 검토 후 수정 요청에 이전 초안이 인용한 근거도 중복 없이 합치도록 변경했다. 추가 검색 분량은 줄이고, 모든 요청의 최종 컨텍스트 검사는 유지한다. 입력 한도에 걸리면 근거를 축소해 새 초안을 만든다. 오류에는 잘못된 인용 ID를 포함하고 검증 이슈를 이벤트로 기록한다. 수정 중 섹션 번호도 제목과 함께 갱신한다. 최종 검증: Rust 19개, Clippy, 통합 검사 및 UI 5개 통과, 취소 약 0.243초.

## 독자 흐름에 따른 문서 구성 (2026-09-13)

기존 결과가 파일·부품별 설명의 모음이 되고 검토 의견까지 본문에 섞이는 문제를 개선했다. 새 목차는 독자 목표·전체 설명 흐름·공통 용어·절별 질문과 다음 단계 연결을 포함한다. 작성 및 수정 요청은 공통 계획과 앞뒤 절의 제한된 문맥을 공유한다. 수정 지시는 독자용 본문에 조용히 반영하며, 사용자 목적에 없는 소스 수정안이나 검토 대화를 본문에 출력하지 않도록 했다.

개별 사실 검토 이후 전체 문서의 연결성·반복·용어·전제 설명 순서를 검토한다. 전역 검토는 발췌 여부를 명시한 제한된 문맥을 사용하고, 문제가 있는 절을 다음 iteration에서 수정한다. 인용은 내부 SHA-256 검증을 유지하면서 게시 본문에서 짧은 각주로 바꾸고, 원본 위치와 전체 ID는 참조에 보존한다. 사용하지 않은 근거는 참조 목록에서 제외한다. 경고 상세와 실행 메타데이터는 본문 앞의 읽기 흐름을 방해하지 않도록 뒤로 옮겼으며 라이브러리 경고 상세는 접어서 표시한다.

검증: Rust 22개, Clippy, TypeScript/Vite 빌드, 로컬 MariaDB와 모의 LLM 통합 검사 및 Playwright 5개 통과. 전역 검토만으로 수정 iteration이 발생하는 경우, 수정 대상에 앞뒤 절 문맥이 전달되는 경우, 기존 목차 역직렬화, 한글 발췌 바이트 제한, 각주 원본 추적 및 브라우저 각주 이동을 확인했다. 기존 실제 결과 파일은 재작성하지 않았고, 이번 변경으로 실제 LLM의 문서 품질이 얼마나 개선되는지는 아직 재측정하지 않았다. 기존 서버는 사용자 승인에 따라 중지했다.
